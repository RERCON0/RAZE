# Безопасность RAZE

- Удаление идёт по дескрипторам и расширенным путям `\\?\`: объект открывается с `FILE_FLAG_OPEN_REPARSE_POINT`, а junction, символические ссылки и точки монтирования удаляются как ссылки — RAZE не заходит в их цель
- Подмена каталога на ссылку посреди удаления не уводит удаление в чужое дерево: каждый объект, включая корневой файл, проверяется по удаляемому дескриптору. Окончательный путь обязан лежать внутри цели, а открытый корень повторно проверяется по списку защищённых мест. При недоступном окончательном пути удаление отклоняется. Владелец и права вне дерева не меняются, а у файла с несколькими жёсткими ссылками — и внутри: владелец, DACL и атрибуты общие на все ссылки, включая лежащие вне цели, поэтому такой файл не трогается вовсе, а удаление открывается через родительский каталог (`FILE_DELETE_CHILD`); если и это невозможно, следует отказ. Исключение — отправка в Корзину: API оболочки работает по пути, и предшествующая проверка запретных мест не атомарна с этой операцией
- Список отказов не зависит от флагов. Не удаляются: корни томов и сетевых шар; сами системные папки и их родители (`Windows`, `Program Files`, `ProgramData`, профиль пользователя, `TEMP`, `APPDATA`, `LOCALAPPDATA`); каталог самой программы. Внутри `Windows` можно удалять только мусорные папки (`Temp`, `Logs`, `Minidump`, `LiveKernelReports`, `SoftwareDistribution`, `Panther`, `Debug`, `Prefetch`, очередь печати), в `Program Files` — не принадлежащие Windows (отклоняются `WindowsApps`, `Windows *`, `Common Files`), в корне системного диска — не служебные (`System Volume Information`, `Recovery`, `Boot`, `EFI` отклоняются; сломанную `$Recycle.Bin` удалить можно)
- Системные каталоги, профиль и каталоги установки получаются через Windows Known Folder API, а не из `SystemRoot`, `ProgramFiles` и других переменных окружения. Недоступность обязательных данных безопасности означает отказ. Нативные UTF-16 имена не преобразуются через текст с потерей суррогатных кодовых единиц; отображаемая строка не используется как путь для удаления, сопоставления карточек или повторного запуска
- Путь проверяется дважды — как введён и как лежит на диске, — поэтому короткое имя (`C:\PROGRA~1`) и junction в родительском каталоге не скрывают защищённое место. Проверка повторяется непосредственно перед удалением, а не только при разборе
- Отклоняются пути с `* ? " < > |`, управляющими символами и двоеточием вне буквы диска (поток NTFS, `::$INDEX_ALLOCATION`): оболочка раскрывает `*` и `?` как маску, а поток — это та же папка под другим именем. Расширенный путь `\\?\` принимается только с буквой диска или UNC; device-пути (`\\.\`, `\\?\PhysicalDrive0`, `GLOBALROOT`, `Volume{…}`) отклоняются. Компоненты `.` и `..` разбираются до проверки, как в `GetFullPathNameW` (после `\\?\` система `..` не разбирает вовсе): `C:\.`, `C:\a\..` и голый `C:` — это корень тома и отклоняются; в явном `\\?\`-пути `..` остаётся дословным и не открывается
- Права меняются только после настоящего `ACCESS_DENIED`, только у объектов внутри цели и только дополнением DACL (полный доступ текущему пользователю, `SYSTEM` и администраторам; существующие записи и NULL DACL сохраняются). Новые ACE не наследуются потомками. Для смены владельца и исправления DACL запрашиваются только необходимые права. Привилегии Backup/Restore/TakeOwnership включаются, лишь если они есть в токене процесса. `--keep-owners` запрещает смену владельца и прав вовсе, и этот параметр сохраняется при перезапуске с правами администратора
- В текстовом режиме UAC запрашивается один раз и только когда без него не обойтись. Повышенная копия получает те же параметры (`--permanent`, `--keep-owners`, `--close-locks`, язык, …) и абсолютные нативные пути только неудавшихся целей после `--`. Родитель сообщает о запуске, а не об успешном удалении. В JSON-режиме автоматической передачи нет: один итоговый отчёт содержит `needs_elevation`, ошибки дают ненулевой код; CLI нужно запускать повышенным явно
- `raze.exe` ставится в системный `Program Files\RAZE` (`raze --install`, один запрос UAC). В эту папку без прав администратора писать нельзя. Прежняя копия из `LOCALAPPDATA\Programs\RAZE` удаляется под связанным неповышенным токеном исходного пользователя; без него требуется ручная очистка. Повышенный процесс не обходит рекурсивно дерево, доступное пользователю для подмены junction. Отложенное удаление запускает PowerShell по абсолютному системному пути, с `LiteralPath` и ограниченным ожиданием, без поиска `cmd`/`ping` через PATH. Бинарники не подписаны: UAC покажет «неизвестный издатель». Копию в доступной для записи папке сборки всё ещё можно подменить перед её повышенным запуском
- Закрытие программ, держащих файл, — вежливое `WM_CLOSE` главным окнам обычных приложений, без `taskkill`: если приложение спросит «сохранить изменения», ответ остаётся за человеком. Службы, Проводник, собственный процесс, системные и критические процессы не закрываются
- «В Корзину» подтверждается уведомлением `IFileOperation` об успешном завершении и созданным объектом Корзины, а не постановкой в очередь. Учитываются настройки тома, политика `NoRecycleFiles` и предел размера; зарезервированные имена, длинные пути, сети, нелокальные диски, ссылки и имена с конечной точкой/пробелом не передаются оболочке как обычные имена. Любой отказ Корзины — отмена или ошибка оболочки — оставляет цель без безвозвратного fallback: без явного согласия (`--permanent-on-bin-failure`, диалога в GUI или диалога контекстного меню) удаления вместо неё не будет. HTML-файл не уносит невыбранный каталог `*_files`. Фактическое безвозвратное удаление оболочкой отражается в режиме отчёта; перенос в Корзину не записывается в освобождённые байты
- Удаление при следующей перезагрузке (`--reboot`) добавляет пары «удалить» в `PendingFileRenameOperations` сеансного менеджера: потомки записываются раньше предков, каждый каталог перед обходом проверяется по дескриптору на принадлежность цели, значение пишется одной пачкой и подтверждается повторным чтением, а превышение лимита значения — честный отказ целиком, не половина плана. Нужны права администратора; без них срабатывает обычный UAC-перезапуск. Исполнение отложено до загрузки — до неё пути ничем не защищены, как у любого отложенного удаления
- Контекстное меню Проводника — это `raze_shell.dll` внутри `explorer.exe`/`dllhost.exe`. Сам он ничего не удаляет: запускает `raze.exe` отсоединённым процессом, пути квотируются по правилам `CreateProcessW`. В общих путях нет `unwrap`/паник, экспортируемые функции проверяют указатели от COM. Клик по пункту меню — это и есть подтверждение для объектов, попадающих в Корзину; цели, удаляемые только безвозвратно, показываются диалогом подтверждения (`--from-shell`), а отказ Корзины и любая неудача — окном с причиной (у такого процесса нет консоли); защитой служат список отказов и Корзина
- Пункт в меню Windows 11 требует подписанного пакета. Пакет подписан самоподписанным сертификатом `CN=RERCON RAZE`; установщик добавляет в `LocalMachine\TrustedPeople` только его **публичную** часть и только если отпечаток совпадает с вшитым в `raze.exe` (`packaging/cert-thumbprint.txt`). Закрытый ключ неэкспортируемый и хранится только в профиле того, кто собирал; повышенный скрипт передаётся через `-EncodedCommand`, а не через файл, и проверяет отпечаток у загруженного объекта, а не у файла на диске. Доверенный сертификат означает, что Windows установит без вопросов любой пакет, подписанный его владельцем: снимается он `raze --uninstall` (или вручную через `certmgr`). Закрепление отпечатка защищает от подмены и порчи `RAZE.cer`, но не от злоумышленника с правами администратора. Без доверия сертификату работает классический пункт меню («Показать дополнительные параметры»)
- Сборка из исходников выпускает собственный сертификат: `packaging\build-package.ps1` создаёт его в вашем хранилище и записывает его отпечаток в `packaging/cert-thumbprint.txt`, после чего `raze.exe` пересобирается. Закреплённое в репозитории значение принадлежит автору
- План ограничен 200 000 объектами и глубиной 512; безвозвратное удаление обходит дерево без лимита числа объектов, но с пределом глубины 512. Неполные счётчики отмечаются в отчётах. GUI принимает до 512 целей и хранит суммарно до 20 000 подробных записей для всех целей; строки списка виртуализированы, не показанные объекты остаются в счётчиках
- Зависимости проверены `cargo audit --deny yanked --deny unsound` (2026-10-12): известных уязвимостей не найдено; остаётся предупреждение о неподдерживаемом `ttf-parser` 0.25.1 из дерева `egui` — [RUSTSEC-2026-0192](https://rustsec.org/advisories/RUSTSEC-2026-0192). Предупреждение не подавлено

## Изменения аудита 2026-10-12

- Исправлены удаление соседнего файла из-за потери UTF-16 имени, удаление read-only без смены владельца и ложный успех при `DELETE_PENDING`
- Защита системных каталогов больше не зависит от подменяемого окружения; восстановление ACL не наследует новые разрешения на чужие потомки
- Закрыты привилегированная очистка изменяемого пользователем дерева и запуск утилит удаления через PATH
- Генератор Ed25519-ключей не перезаписывает существующие файлы, отклоняет совпадающие пути и ограничивает ACL только приватного файла, не родителя; проверка релиза проверяет PE DLL и подписи архива
- Исправлены итоговый JSON, коды ошибок и повторный запуск только неудавшихся нативных целей; GUI сохраняет выбранный язык между запусками и не теряет цели после предварительной проверки
- Удалены тесты, копировавшие константы, проверявшие только непустоту или поведение стандартной библиотеки. Проверка удержания COM-сервера проверяет наблюдаемый `DllCanUnloadNow`, включая повторный `LockServer(false)`, а не внутренний счётчик
- Корзина, отказавшая по любой причине, больше не переходит молча к безвозвратному удалению: без явного согласия (`--permanent-on-bin-failure`, диалога GUI или диалога контекстного меню) цель остаётся, а отчёт говорит почему; из контекстного меню безвозвратные объекты подтверждаются диалогом
- У файла с несколькими жёсткими ссылками владелец, DACL и атрибуты не меняются: они общие на все ссылки; удаление открывается через родительский каталог (`FILE_DELETE_CHILD`), иначе следует отказ
- Исчезнувшие до удаления объекты больше не записываются в счётчики удалённого и освобождённых байтов
- Добавлено удаление при следующей перезагрузке (`--reboot`) и подтверждение безвозвратных объектов при вызове из контекстного меню
- Добавлен CI (fmt, clippy, тесты, релизная сборка, аудит зависимостей и скан истории), а README ведёт на страницу скачивания готовой сборки

Проверены реальные CLI-операции, native GUI с перезапуском и удалением тестовой
цели, операции Корзины, генерация ключей и проверка подписанного архива.
